Add to PATH, in powershell:
$links = "$env:LOCALAPPDATA\Microsoft\WinGet\Links"
$userPath = [Environment]::GetEnvironmentVariable("Path", "User")

if (($userPath -split ";") -notcontains $links) {
    [Environment]::SetEnvironmentVariable(
        "Path",
        (($userPath.TrimEnd(";") + ";" + $links).Trim(";")),
        "User"
    )
}

dbt Setup
> uv add dbt
> dbt --version
    dbt 2.0.12

> dbt init --project-name analytics --skip-profile-setup

If you have to create a profiles.yml on your own,
you can create it inside this folder:
C:\Users\[name]\.dbt\profiles.yml
i. Create a separate folder for data within the project folder
    > mkdir data
ii. In the profiles.yml, it may be indicated with: path: ../data/dev.duckdb

Navigate to the [project] folder, in this case is 'analytics'
> cd analytics
> dbt debug
> dbt ls

seed, run, test:
> dbt seed
> dbt run
> dbt test

DuckDB:
> duckdb ../data/dev.duckdb
> show tables;

Clean - deletes the folders listed in clean-targets
> dbt clean
> dbt compile
> dbt run
> dbt show --select customers

If you need a GUI for DuckDB:
> duckdb ../data/dev.duckdb -ui

Get sample data
> python ./scripts/download_data.py

Using jinja
{{ ... }}, {% statement_here %}, {# Jinja comment here #}

> code models/jinja_demo.sql
> dbt compile --select jinja_demo

Using select (--select)
> code models/top_locations.sql
> dbt run --select +top_locations
The use of + sign:
    If +model_name -> it builds all its dependencies first before compiling this model
    If model_name+ -> it also builds downstream models after it is compiled.

Check the duckdb
> duckdb ../data/dev.duckdb
